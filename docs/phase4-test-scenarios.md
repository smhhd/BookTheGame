# سناریوهای تست دستی فاز چهارم

## پیش‌شرط

```bash
docker compose up --build
curl http://localhost:3000/health/search
```

در اجرای Docker، مسابقات Seed نسبت به زمان ایجاد دیتابیس در آینده ساخته و Index
به‌صورت خودکار پر می‌شود. برای Volume قدیمی، دیتابیس را بدون حذف ناخواسته داده
به‌روزرسانی کنید یا در محیط تست Volume را بازسازی و سپس Reindex کنید.

## سناریوی جستجو، رزرو و پرداخت

1. `http://localhost:5173` را باز کنید و متن/شهر/قیمت را فیلتر کنید.
2. URL را Refresh کنید؛ فیلتر و صفحه باید حفظ شود.
3. یک بلیت موجود را باز و «ورود برای رزرو» را انتخاب کنید.
4. ثبت‌نام کنید؛ باید به صفحه همان بلیت/رزرو برگردید.
5. رزرو را تأیید کنید؛ `reservedUntil` و شمارش معکوس باید دیده شود.
6. پرداخت کارت آزمایشی را انجام دهید.
7. در «رزروهای من»، وضعیت `پرداخت‌شده` را بررسی کنید.
8. درخواست جستجو را دوباره اجرا کنید؛ بلیت فروخته‌شده نباید در
   `remainingOnly=true` دیده شود.

## سناریوی کنسلی

1. بلیت موجود دیگری را رزرو و پرداخت کنید.
2. در تاریخچه «لغو رزرو» را انتخاب کنید.
3. درصد جریمه و مبلغ استرداد Server را بررسی و تأیید کنید.
4. وضعیت `لغوشده` و افزایش کیف پول را در پروفایل بررسی کنید.
5. جستجو را Refresh کنید؛ صندلی آزادشده باید دوباره موجود باشد.

## سناریوی انقضا

1. بلیت را رزرو و پرداخت نکنید.
2. پس از `RESERVATION_TTL_MINUTES` و اجرای Job، Active را Refresh کنید.
3. رزرو باید در تاریخچه `منقضی` و بلیت دوباره در جستجو موجود باشد.

## گزارش و پشتیبان

1. کاربر برای یک رزرو گزارش ثبت و وضعیت pending را مشاهده کند.
2. با OTP حساب Seed به نام `support1@example.com` وارد شوید (در Docker مقدار
   `EXPOSE_DEV_OTP=true` است).
3. پنل پشتیبان باید قابل مشاهده باشد؛ گزارش را پاسخ دهید و وضعیت را تغییر دهید.
4. با حساب spectator مستقیماً `/support` را باز کنید؛ UI باید Redirect کند.
5. درخواست مستقیم `/api/admin/reports` با JWT spectator باید `403` بدهد.

## قطع Elasticsearch و بازیابی

```bash
docker compose stop elasticsearch
curl "http://localhost:3000/api/tickets?q=Football"
docker compose start elasticsearch
docker compose run --rm search-indexer
```

در قطع Elastic، پاسخ باید `search.source=postgresql-fallback` داشته باشد. پس از
راه‌اندازی و Reindex، منبع باید دوباره `elasticsearch` شود. وضعیت Sync در
`/health/search` قابل بررسی است.
